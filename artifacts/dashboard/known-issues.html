Dashboard 03 · Review boundary

Known Issues

자동화의 제한과 제품 접근성 검토 항목을 섞지 않습니다. 같은 실행에서 보이더라도 ownership과 다음 조사가 다를 수 있습니다.

Automation / structure

해석에 영향을 주는 제한

  • 최신 HEAD의 physical-device 32-scenario Full Validation evidence freshness 갱신 필요
  • WebView, Compose, merged node, lazy content와 dynamic hierarchy의 일반화 gap
  • 향후 Candidate의 portable observation bundle 자동 첨부는 아직 일반화되지 않음
  • Comparator history는 backend process memory 범위이며 remote CAS/durable shared history 없음
  • container hierarchy evidence와 positive recovery corpus가 제한적
  • plugin discovery와 exact reviewed model policy의 범위 밖 단말은 별도 검토 필요
  • plugin onboarding rollback은 preview only
  • V10 Controlled Routing은 구현되지 않음

Separate the signal

제품 접근성 검토 vs 자동화 진단

QA Review

제품 접근성 검토 항목

qa_accessibility signal은 visible text와 TalkBack speech, focus/evidence를 사람이 확인해야 하는 대상입니다. Review Required의 QA Review count에 포함됩니다.

Automation Diagnostics

자동화 진단 항목

automation_engine signal은 traversal, recovery, artifact, environment 또는 engine을 조사할 대상입니다. QA 접근성 결함으로 자동 승격하지 않습니다.

주의: evidence freshness ≠ product FAIL

현재 근거가 오래되었거나 특정 corpus가 부족하다는 표시만으로 제품 접근성 FAIL을 선언하지 않습니다. 새 실행, 재현, reviewer decision이 필요한 상태와 실제 접근성 결함은 각각의 evidence로 판단합니다.
