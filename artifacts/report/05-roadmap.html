보고서 05 · 향후 설계 방향

향후 개선 방향

현재처럼 객체를 하나씩 지정하는 방식에서 벗어나, 화면에 도달한 뒤 현재 화면의 접근성 객체를 자동으로 발견하고 실제 TalkBack 순회 결과와 대조하는 구조로 발전시키는 것이 장기 목표입니다.

향후 설계 방향

State-Graph 기반 접근성 자동 탐색은 현재 실제 운영 순회가 아닙니다. 현재 구현은 시나리오 중심 순회와 Traversal Identity V2를 사용하며, 아래 내용은 Audit, SMART_NEXT, 증거 수집과 결과 대조를 통합·확장하기 위한 후속 설계입니다.

  • 시나리오에 따라 TalkBack 순회

↓

향후 · 화면 상태 중심

  • 목표 화면까지 이동
  • 현재 화면의 객체를 자동 발견
  • 실제 TalkBack으로 전체 순회
  • 예상 객체와 실제 방문 결과 대조
  • 안전한 메뉴·탭을 따라 다음 화면 탐색

유지보수의 중심을 이동

앱·플러그인 변경으로 화면 이동 경로, resource-id, anchor, 개별 대상, 순회 규칙과 복구 규칙을 조정해야 할 수 있습니다.

화면 도달 → 현재 화면의 트리 수집 → 후보 객체 자동 발견
→ 실제 포커스·발화·증거 수집 → 예상 결과와 실제 방문 결과 대조

목표는 유지보수를 없애는 것이 아닙니다. 개별 객체를 매번 다시 지정하는 작업을 줄이고, 화면 진입과 예외 처리 중심으로 유지보수 범위를 좁히는 것입니다.

Navigation은 사라지지 않습니다

Home → Devices → plugin → detail처럼 의미 있는 화면·상태로 가는 화면 이동은 계속 필요합니다. 이 경로는 anchors, screen identity와 범위를 제한한 fallback 규칙을 사용할 수 있습니다.

화면 안에 도달한 뒤에는 화면 내부의 객체를 분석하고 검증하는 Accessibility Audit 단계가 자동 발견과 TalkBack 순회 중심으로 동작하도록 역할을 나눕니다.

안전한 탐색을 위한 구분

발견된 객체를 세 가지로 구분

읽기 / 검증 객체

텍스트, 라벨 등 TalkBack으로 읽고 검증하면 되는 객체입니다. 자동 탐색 과정에서 임의로 실행하지 않습니다.

안전한 화면 이동 객체

탭, 더보기, 펼치기처럼 새로운 정보 영역을 보여 주면서 위험한 상태 변경을 일으키지 않는 객체입니다. 기술적으로는 Safe Navigation Object라 부를 수 있습니다.

동작 / 위험 객체

ON/OFF, 삭제, 초기화, 저장, 결제처럼 실제 상태를 바꾸는 객체입니다. 일반 자동 탐색에서는 실행하지 않고 명시적인 시나리오나 정책으로만 제어합니다.

기존 Audit과 Smart Move를 버리지 않는 확장

Audit검증 후보 정의
TalkBack 순회실제 방문 객체 확인
발화 / 증거실제 노출 정보 기록
결과 대조예상 객체와 실제 방문 비교
안전한 화면 이동다음 화면 상태 탐색

초기 Smart Move의 ‘다음 객체로 이동하고 필요하면 스크롤한다’는 개념은 Accessibility Tree 분석, 포커스 식별 정보, 복구와 결과 대조로 확장되었습니다. 다만 현재 모든 이동이 SMART_NEXT를 사용하는 것은 아니며, 결정적 대상 경로와 fallback을 함께 보존합니다.

단계 중심 로드맵

로드맵 성숙도

현재 기반
이미 활용 가능한 기능

Accessibility Tree/XML 수집, Audit 후보와 커버리지, Traversal Identity, 운영 순회, SMART_NEXT 관련 기능, 스크롤·복구, 발화·증거 수집, 결과 대조 기능이 이미 기반으로 존재합니다.

다음 검토
코드 기준 차이 분석

후보 객체 정의 방식, 객체 identity, 예상 발화 생성, 실제 포커스 매칭, MISSED/UNEXPECTED 판정, 안전한 화면 이동 분류, 화면 상태 식별, 반복·무한 탐색 방지를 검토합니다.

중장기 목표
자동 접근성 탐색 확대

앱·플러그인 버전 변화와 locale/device 차이에 대응하고, 화면 상태 커버리지를 넓히며, 충분한 검증 후 자동 탐색 범위를 단계적으로 확대합니다.
