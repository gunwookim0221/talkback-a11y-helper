실제 운영 기능

실제 실행 계층

현재 운영 순회는 `collection_flow`와 `TraversalCoordinator`를 중심으로 동작합니다. Traversal Identity V2가 기본으로 켜져 있고, 강한 closed evidence(완결된 증거)만 진행·방문·중지·복구 판정에 제한적으로 사용합니다.

불완전하거나 판단을 확정할 수 없는 결과, `MOVE_TO_OTHER_NODE`, `SNAP_BACK`은 Legacy fallback으로 남습니다. `TB_TRAVERSAL_IDENTITY_V2_ENABLED=0`인 run은 명시적인 Legacy Compatibility입니다.

진단 / Shadow

관찰·분석 계층

Coverage Probe, Audit, Identity Shadow와 V10 Runtime Inventory/Quick Identify/Shadow Compare는 증거와 준비도를 보강합니다.

V10 Controlled Routing은 구현되지 않았습니다. Shadow의 `READY`나 `MATCH`는 실제 운영 순회를 자동으로 바꾸지 않습니다.

Evidence Ledger와 Coverage는 같은 것이 아닙니다.

Evidence Ledger는 transaction correlation(트랜잭션 연계)과 V2 결과 대조를 지원하는 append-only 증거 경로입니다. Coverage Probe와 커버리지 상태는 포커스 대상 후보와 커버리지를 보강하는 검증기용 진단입니다. 둘 다 명시된 운영 판정 기준과 제품 판정을 임의로 대체하지 않습니다.

제품 접근성 검토

실제 접근성 품질 검토 대상입니다. Review Required의 QA Review 항목 수에 포함됩니다.

자동화 진단

순회, 복구, 결과물, 실행 환경 또는 엔진을 조사할 신호입니다. QA 발견 항목과 자동으로 합치지 않습니다.

사람의 결정

Candidate 승인과 Baseline 변경은 사람이 검토하고 명시적으로 결정합니다.
