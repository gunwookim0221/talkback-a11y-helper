실제 실행 계층

현재 Production Traversal은 `collection_flow`와 `TraversalCoordinator`를 중심으로 동작합니다. Traversal Identity V2가 기본 ON이고, 강한 closed evidence만 progress/visit/stop/recovery에 제한적으로 사용합니다.

불완전하거나 indeterminate한 결과, `MOVE_TO_OTHER_NODE`, `SNAP_BACK`은 Legacy fallback으로 남습니다. `TB_TRAVERSAL_IDENTITY_V2_ENABLED=0`인 run은 명시적인 Legacy Compatibility입니다.

Diagnostic / Shadow

관찰·분석 계층

Coverage Probe, Audit, Identity Shadow와 V10 Runtime Inventory/Quick Identify/Shadow Compare는 evidence와 readiness를 보강합니다.

V10 Controlled Routing은 구현되지 않았습니다. Shadow의 `READY`나 `MATCH`는 production traversal을 자동으로 바꾸지 않습니다.

Evidence Ledger와 Coverage는 같은 것이 아닙니다.

Evidence Ledger는 transaction correlation과 V2 reconciliation을 지원하는 append-only evidence 경로입니다. Coverage Probe/coverage health는 focusable candidate와 coverage를 보강하는 validator-facing 진단입니다. 둘 다 명시된 production gate와 제품 verdict의 의미를 임의로 대체하지 않습니다.

QA accessibility

실제 접근성 품질 검토 대상입니다. Review Required의 QA Review count에 포함됩니다.

Automation diagnostic

traversal, recovery, artifact, environment 또는 engine을 조사할 신호입니다. QA finding과 자동으로 합치지 않습니다.

Human decision

Candidate 승인과 Baseline 변경은 사람이 review하고 명시적으로 결정합니다.
